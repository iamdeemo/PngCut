# PngCut Windows 版设计

## 目标与范围

在不改变 PngCut 现有交互逻辑和离线处理原则的前提下，提供原生 Windows 客户端。

- 系统：Windows 11、Windows 10，以及 Windows 7 SP1。
- 架构：分别提供 x64 与 x86 免安装 ZIP。
- 名称与图标：用户可见名称为 `PngCut`；沿用现有 SVG 图标，并生成多尺寸 `.ico`。
- UI：Win11 风格的圆角、留白、卡片层级、Fluent 风格线性图标和浅色主题。
- 非目标：不创建安装程序、不联网、不加入账号/API 服务，不依赖 Windows 11 专属 Mica 或 WinUI 运行时。

## 技术方案

采用独立的 WPF + .NET Framework 4.8 工程，不修改 macOS 工程的构建或发布路径。

- WPF 在 Windows 10/11 使用同一套 Win11 视觉主题；不使用会阻断旧系统的 WinUI 3、Mica 或系统标题栏材质。
- Windows 7 SP1 使用同一可执行程序：禁用透明和可选阴影增强，保留相同的布局、控件和所有功能。用户不需要手动设置兼容模式。
- Windows 11 自带 .NET Framework 4.8/4.8.1；Windows 7 缺失 .NET Framework 4.8 时，启动器显示中文说明与微软官方安装入口。
- 压缩程序作为应用内资源分发，并按应用包架构调用：oxipng（PNG 无损）、pngquant（PNG 平衡）和 MozJPEG（JPG/JPEG）。不上传图片。
- 压缩二进制尽量静态构建，避免 Visual C++ 运行库前置条件；其许可证与应用、发布说明一并保留。

## UI 与交互

Windows 版保留 macOS 版已确认的交互语义，而非逐像素复制 macOS 外观。

1. 主窗口包含文件拖放区、选择文件按钮、任务列表、底部“无损/平衡”切换、打开输出文件夹和设置入口。
2. 设置以底部抽屉/覆盖层呈现；点击遮罩关闭。内容包括输出位置与 PNG 压缩方式。抽屉有短、系统感的滑动动画；旧系统可降级为无透明效果。
3. 所有主要控件使用统一圆角、至少 44px 的可点击区域，并使用同一 SVG 派生的线性图标系统。
4. UI 自动按输入选择引擎：PNG 无损使用 oxipng，PNG 平衡使用 pngquant，JPG/JPEG 使用 MozJPEG 并在列表显示“平衡”。
5. 输入可以是文件或文件夹；递归发现 PNG/JPG/JPEG，非图片计数提示但不阻塞任务。

## 输出、任务与数据

- 单图片的“原文件旁边”输出为 `<原名>_pngcut.<原扩展名>`。
- 导入文件夹时，在源文件夹同级创建 `<文件夹名>_pngcut`，保持内部相对目录和图片文件名。
- 支持指定输出文件夹与覆盖原文件；每个任务先写临时文件，校验完成后原子提交。
- 任务串行执行。单项失败仅标记该项，可重试，不阻塞后续任务。
- 压缩完成时冻结原始字节数、压缩后字节数和节省比例。以后即使删除源文件或输出文件，任务列表中的历史统计不再改变。
- 偏好设置保存在 `%AppData%\\PngCut`，包括输出策略和压缩模式；不保存 API 密钥，因为应用完全离线。

## 分发与合规

- 发布 `PngCut-Windows-x64.zip` 与 `PngCut-Windows-x86.zip`；解压并双击 `PngCut.exe` 即可使用，不写注册表、不需要管理员权限。
- ZIP 内包含程序、对应架构压缩组件、图标资源、简体中文使用说明和许可证/第三方声明。
- 因 pngquant 使用 GPL v3 或更高版本，Windows 源码与对应构建脚本须在与发布包同等可访问的位置提供，并保留许可证声明。

## 验收与测试

每个架构包在 Windows 7 SP1、Windows 10、Windows 11 各验证以下项目：

1. 直接解压启动；缺失 .NET Framework 的 Win7 显示中文可操作提示。
2. PNG 无损、PNG 平衡、JPG/JPEG 均可完成离线压缩，且不会产生网络请求。
3. 单文件、嵌套文件夹、指定输出、覆盖原文件和冲突命名均遵循输出规则，且不会损坏原图。
4. 失败项重试与后续任务继续运行。
5. 删除完成任务的输出文件后，任务列表仍显示压缩完成时冻结的数据。
6. Win10/11 的 Win11 风格、Win7 的降级视觉和 44px 点击区域均通过手动视觉与交互检查。

## 边界与风险

- WPF/.NET Framework 4.8 允许支持 Win7，但旧系统安全更新已终止；本项目只保证应用兼容性，不承诺操作系统安全性。
- 为维持 Win7 兼容性，不采用真正的 Mica 和 Win11 系统级标题栏材质；视觉效果由应用自身绘制。
- x86/x64 需要分别构建和测试压缩二进制，不能在运行时混用。
