# pngcut GIF 压缩与 PNG 序列转 GIF 设计

**状态：** 已确认

**范围：** macOS `FFPNG` 客户端；Windows 移植不在本次实现范围内。

## 目标

在保持 pngcut 现有离线、本地处理、批量导入、串行队列和输出安全策略的前提下，新增：

1. 导入 GIF 后使用 Gifsicle 压缩。
2. 自动识别同一批导入中的 PNG 序列，并在适当的用户确认后使用 Gifski 生成 GIF。
3. 延续全局“无损 / 平衡”处理代号和现有设置抽屉的交互逻辑。

所有处理均在本机完成，不上传文件，也不访问网络服务。

## 非目标

- 不实现 Windows 端功能。
- 不将视频转 GIF。
- 不自动缩放、裁切或补帧 PNG 序列。
- 不开放 Gifski 质量、Gifsicle 优化等级或序列数量阈值的用户设置。
- 不把 PNG 序列转 GIF 描述为像素级无损；“无损”只是不改变软件统一处理代号。

## 统一模式与引擎路由

现有底栏及设置中的“无损 / 平衡”继续是每项任务的统一处理代号。设置抽屉中原“PNG 压缩方式”分组改为“压缩方式”，控件与行为不变。

| 输入类型 | 无损 | 平衡 |
| --- | --- | --- |
| 单张 PNG | oxipng | pngquant（现有质量范围与不增大保护） |
| JPG/JPEG | MozJPEG（现有行为） | MozJPEG（现有行为） |
| 既有 GIF | `gifsicle -O3` | `gifsicle -O3 --lossy=200` |
| PNG 序列生成 GIF | Gifski `--quality 100` | Gifski `--quality 80` |

Gifsicle 的 `-O3` 是最强无损优化等级；平衡模式的 `--lossy=200` 为强有损压缩，允许出现色带、颗粒或细节损失。既有 GIF 只有在结果小于原文件时才保存，否则任务显示为未变更。Gifsicle 的 `-O3` 本身不保证结果一定变小。

Gifski 编码始终是格式转换：不以输出必须小于源 PNG 总大小作为保存条件。成功生成的 GIF 直接保存。

## 设置抽屉

新增“GIF 设置”分组，视觉样式与现有设置抽屉一致：分组标题、单选行、系统字体与现有间距。只有布尔选项使用单一复选框对勾。

### PNG 序列转 GIF

- 复选框标签：`开启 PNG 序列转 GIF`。
- 初始默认值为未勾选。
- 勾选表示序列转换意图开启；未勾选表示以普通 PNG 压缩为默认行为。
- 导入判定和用户确认会按“导入决策”规则同步该勾选状态。

### GIF 帧率

- 单选预设：20、25、30 FPS；默认 30 FPS。
- `自定义`单选行后跟整数输入框。
- 自定义值的有效范围为 1–50。输入合法值后选中自定义；用户选择预设后以预设值为准。
- 非法或空自定义值不覆盖上一个有效帧率，并显示输入校验提示。

### GIF 循环

- 单选项：`无限循环`（Gifski repeat 为 `0`）和`播放一次`（Gifski repeat 为 `-1`）。
- 默认无限循环。

复选框状态、最后一个有效 FPS、FPS 选择来源和循环方式均持久化到现有 `UserDefaults` 设置中。

## PNG 序列检测

文件夹导入继续使用当前递归发现逻辑；检测只在每一次导入的已发现 PNG 集合上运行，不额外扫描单个 PNG 所在的父目录。

一个候选序列必须同时满足：

1. 全部文件位于同一目录。
2. 文件名具有相同命名骨架，且扩展名为 `.png`。
3. 编号是去除扩展名后的末尾数字；支持任意起始编号和有无零填充。
4. 编号连续、无缺口，且连续文件不少于 10 张。

检测按数值自然顺序排序，而非字符串字典序。例如 `walk_1.png`、`walk_2.png`、`walk_10.png` 的顺序正确；不同目录下的同名组绝不合并。没有编号、数量不足、存在编号缺口的 PNG 仍是普通 PNG。

检测阶段只读路径、文件名和基础文件属性。仅对已命中的候选组读取每帧 PNG 头部尺寸，且所有帧必须宽高完全一致。尺寸不一致时创建失败任务并提示“帧尺寸不一致，无法转 GIF”；不缩放、裁切、补帧或静默改走普通压缩。

## 导入决策

同一批导入允许同时包含 PNG 序列、普通 PNG、JPG/JPEG 和 GIF。有效序列转 GIF，普通 PNG/JPG/JPEG 继续按当前模式压缩，既有 GIF 使用 Gifsicle。

| 检测结果 | 复选框状态 | 用户交互与结果 |
| --- | --- | --- |
| 发现尺寸有效的 PNG 序列 | 未勾选 | 弹窗询问是否转 GIF。确认后转 GIF 并勾选；拒绝后将该序列各 PNG 按普通压缩处理，保持未勾选。 |
| 发现尺寸有效的 PNG 序列 | 已勾选 | 直接转 GIF，不再重复询问。 |
| 未发现有效序列 | 未勾选 | 正常压缩可处理文件。 |
| 未发现有效序列 | 已勾选 | 弹窗询问是否改为压缩。确认后压缩并取消勾选；拒绝后提示“当前文件夹没有 PNG 序列，无法转 GIF”，保持勾选，当前批次不处理。 |

一次导入可能有多组候选序列。首次需要确认时，弹窗列出组数、各组名称与帧数，用户对该批次作出一次转换或压缩选择，避免逐组打扰。

## 输出策略

常规 PNG/JPG/JPEG/GIF 继续复用现有三种输出位置、临时同级文件、原子提交、冲突避让和文件夹相对目录规则。

PNG 序列生成 GIF 也复用相同位置语义，但“覆盖原文件”必须执行安全例外：

- 永远保留全部源 PNG。
- 直接导入的 `walk_0001.png` 至 `walk_0010.png` 输出为 `walk.gif`；若已存在则追加不冲突序号。
- 文件夹导入沿用现有在源文件夹同级创建 `<文件夹>_pngcut`、保留相对目录结构的规则；对应位置生成 `walk.gif`。
- 指定输出文件夹时，生成同名 GIF，并沿用现有冲突避让规则。
- 用户选中“覆盖原文件”时，序列 GIF 改按安全的“原文件旁边”规则输出，不删除或替换任何源帧。

## 架构与队列

新增边界清晰的组件，避免将序列分组、尺寸校验、命令参数和 UI 决策混进现有文件发现或队列代码：

- `FileDiscovery`：扩展识别 GIF，继续只负责文件与目录发现。
- `PNGSequenceDetector`：纯文件名分组、阈值与自然排序；可由单元测试完全覆盖。
- `PNGSequenceValidator`：仅对候选组校验帧尺寸。
- `GIFProcessingConfiguration`：将统一模式、FPS、循环设置转换为 Gifsicle/Gifski 参数。
- `GifsicleCompressor`：处理单个 GIF，并比较临时输出与源文件大小。
- `GifskiSequenceEncoder`：处理多个、已排序且已校验的 PNG 帧，写入一个临时 GIF。
- 任务输入模型：支持单文件和 PNG 序列两种输入；序列任务记录全部源 URL、显示名、帧数与源文件总大小。
- `OutputPlanner`：增加生成 GIF 的安全规划入口，复用已有的目录、预留目标和原子提交机制。

文件枚举、序列分组和候选尺寸读取在 utility 优先级后台执行。弹窗、设置变更、任务状态发布和输出 URL 预留回到主线程；导入决策串行化，避免多个同时拖入批次出现并发弹窗或输出路径冲突。压缩队列继续一次处理一个任务，保留已有的重试行为。

任务行继续使用现有文件名、统一处理代号、大小、进度、状态和“重试”布局。序列任务的显示名是输出 GIF 名，例如 `walk.gif`，并显示 `10 张 PNG`；其原始大小为全部帧大小之和。

## 错误处理

下列情况必须有明确、可重试或可理解的任务反馈，并确保临时文件被清理、源文件不被改动：

- 内置 Gifsicle 或 Gifski 缺失、无执行权限或架构不匹配。
- 子进程非零退出、诊断输出、未生成文件或生成空文件。
- PNG 序列帧尺寸不一致。
- 自定义 FPS 非整数或不在 1–50。
- 导入后源文件被移走、权限变化或无法读取。
- GIF 无损/平衡处理得到与原文件相同或更大的结果。
- 用户在“未发现序列”提示中拒绝普通压缩。

## 构建、资源与许可证

与现有 oxipng、pngquant、MozJPEG 一致，新增可复现的 macOS arm64/x86_64 构建脚本、版本锁定、资源目录、执行权限校验和发布内容检查：

- Gifsicle 二进制与许可证文本。
- Gifski 二进制与许可证文本。
- `THIRD_PARTY_NOTICES.md`、README、DMG 内容校验的同步更新。
- 对应版本的上游源码取得方式与构建说明。

Gifski 为 AGPL-3.0-or-later，Gifsicle 为 GPL-2.0-only。两者以独立的本地命令行程序随 macOS 应用分发；发布前必须保留许可证、对应源码信息，并完成发行合规复核。

## 验收与测试

单元测试至少覆盖：

1. GIF 文件发现、普通文件跳过，以及原有 PNG/JPG/JPEG 行为不回归。
2. 10 帧阈值、少于 10 帧、缺帧、不同目录、不同命名骨架、零填充、自然排序和混合导入。
3. 帧尺寸一致与不一致的判定。
4. 导入决策表中的四种状态转换、弹窗选择和复选框同步。
5. 两个统一模式到 Gifsicle/Gifski 的命令参数映射。
6. 20/25/30 FPS、自定义 FPS 的校验与持久化，以及无限循环/播放一次的参数映射。
7. 直接文件、文件夹、指定输出目录、重名和“覆盖原文件”例外下的 GIF 输出路径。
8. Gifsicle 不增大保护、临时文件清理、子进程失败、缺少二进制和重试。
9. 任务行的序列显示名、帧数、总源大小和可访问性标签。

UI 测试覆盖 GIF 可选/可拖入、GIF 设置控件、确认弹窗、尺寸不一致提示、任务行与设置状态同步。发布前运行 macOS Release 构建、完整单元/UI 测试以及 DMG 挂载与资源存在性校验。
