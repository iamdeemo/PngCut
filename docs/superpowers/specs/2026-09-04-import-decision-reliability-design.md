# PngCut 导入决策防呆与可靠展示设计

**状态：** 已确认，待实现  
**范围：** macOS PngCut 的“PNG 序列转 GIF”导入决策；不改变压缩引擎、序列检测规则或输出策略。

## 问题

现有逻辑在以下两种情况下需要用户确认：

1. “开启 PNG 序列转 GIF”关闭且导入中发现有效 PNG 序列。
2. “开启 PNG 序列转 GIF”开启且导入中未发现有效 PNG 序列。

当前实现将确认状态和提示状态分别绑定到同一根视图上的多个原生 alert。确认界面未显示时，导入模型仍保留等待确认的临时状态；后续导入被队列守卫拦截，用户只能重启应用恢复。

## 目标

- 每次需要确认时，都显示一个明确、唯一且不能静默消失的导入决策窗口。
- 决策窗口显示期间，应用明确禁止新的拖入和选文件操作，而不是让用户误以为软件无响应。
- 每一个确认、取消和提示完成分支都释放临时状态；任何一次选择后都可以继续导入，无需重启。
- 保持既定的四种“检测结果 × 开关状态”业务规则与设置同步语义。

## 非目标

- 不改变“同目录、同命名骨架、末尾连续编号、至少 10 张”的序列检测条件。
- 不改变 Gifsicle、Gifski、帧率、循环、压缩模式、输出目录或覆盖原文件的规则。
- 不添加每次导入前手动选择模式的步骤。

## 交互设计

界面使用一个应用内居中遮罩 `ImportDecisionOverlay`，而不是多个并列的系统 alert。它只读取一个模型状态 `activeImportDecision`，状态为 `nil` 时不显示。

遮罩显示期间：

- 拖入区域不再接受拖放，不显示可投放的浅蓝状态。
- “选择文件”和任务列表中的“添加文件”按钮禁用。
- 设置仍可见但不可通过遮罩操作；遮罩文案说明“请先完成当前导入选择”。
- 遮罩没有关闭按钮、Esc 关闭或点击背景关闭行为；用户只能选择可见的业务操作，避免产生未处理的隐式取消。

### 导入规则

| 导入检测结果 | 开关当前状态 | 决策窗口与结果 |
| --- | --- | --- |
| 发现有效 PNG 序列 | 关闭 | 显示“发现 PNG 序列”。“转 GIF”将开关设为开启并转换；“常规压缩”保持开关关闭并压缩全部帧。 |
| 发现有效 PNG 序列 | 开启 | 不显示决策窗口，直接转换为 GIF。 |
| 未发现有效 PNG 序列 | 关闭 | 不显示决策窗口，直接进行常规压缩。 |
| 未发现有效 PNG 序列 | 开启 | 显示“未发现 PNG 序列”。“常规压缩”将开关设为关闭并压缩；“不压缩”保留开关开启且不处理本批。 |

“不压缩”不会关闭遮罩后再触发另一套 alert；同一个遮罩切换为提示页，显示“当前文件夹没有 PNG 序列，无法转 GIF”，仅提供“好”按钮。“好”会关闭遮罩并恢复导入能力。

一个批次同时有候选序列与普通 PNG/JPG/GIF 时，转换或常规压缩的选择沿用当前批次规则：选转换时，序列生成 GIF，普通文件按常规压缩；选常规压缩时，序列帧和普通文件都按常规压缩。

## 状态模型

用单一的 `ImportDecision` 取代彼此独立的 `pendingImportPrompt` 和 `importNotice`：

- `sequenceDetected(resolution)`：等待“转 GIF”或“常规压缩”。
- `noSequenceDetected(resolution)`：等待“常规压缩”或“不压缩”。
- `noSequenceNotice`：显示无法转换的说明，等待“好”。

`activeImportDecision` 是导入可见状态的唯一来源。导入队列仅在它为 `nil`、没有进行序列预检，且没有活动批次时推进。

每一个窗口按钮通过一个专用的模型方法完成原子状态转换：先取得当前批次，再清空 `activeImportDecision` 与活动批次，最后同步开关并入队或转到提示页。任何 guard 失败、预检失败或任务规划失败也必须清理活动批次；只有明确进入 `noSequenceNotice` 时才保留遮罩状态。

## 组件边界

- `AppModel`：只负责发现结果、创建和消费 `ImportDecision`、同步 GIF 设置、推进 FIFO 导入队列。它不负责 SwiftUI 呈现。
- `ImportDecisionOverlay`：只呈现一个当前决策及其按钮，不自行推断文件类型、开关或队列状态。
- `MainWindowView`：根据 `activeImportDecision` 叠加遮罩，并用同一个“导入被决策窗口锁定”的布尔值禁用拖放和选择文件入口。

这样 UI 展示失败不会留下模型中不可见的等待状态；模型也不依赖多个 SwiftUI presentation modifier 的叠加顺序。

## 错误处理与恢复

- 任何非预期地失去活动批次的情况，必须释放决策状态并记录诊断信息，不得永久阻塞后续导入。
- 点击“常规压缩”“转 GIF”或提示页“好”后，下一次导入必须立即可用。
- 文件发现为空或只有不支持格式时，不创建决策窗口，也不改变 GIF 开关。
- 输入锁仅覆盖用户未完成选择的时段；开始压缩或 GIF 编码后，用户可再次导入，任务仍按现有 FIFO 队列运行。

## 验收与测试

单元测试必须覆盖：

1. 四种检测结果与开关状态的处理规则和开关最终状态。
2. 两种决策路径的每一个按钮都清空活动决策；“不压缩”仅转入同一决策窗口的提示页。
3. 处理完任一决策后，再导入 PNG、GIF 和有效序列均能被正常接收，无需重建 `AppModel`。
4. 两个连续需要确认的批次按 FIFO 逐个出现，前一批结束后下一批才能显示。

UI 测试必须覆盖：

1. 两种需要确认的场景都会显示具有稳定 accessibility identifier 的遮罩。
2. 遮罩出现时，拖入和选文件入口禁用；遮罩结束后恢复。
3. “不压缩”在同一遮罩中显示提示，点击“好”后可立即再次导入。
4. 连续触发四种状态组合时，不会出现不可见弹窗、永久禁用或需要重启的状态。
