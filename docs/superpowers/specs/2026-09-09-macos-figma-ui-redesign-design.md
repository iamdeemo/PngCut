# PngCut macOS Figma UI 与动效重设计

**状态：** 已确认，待用户审核规格

**范围：** 仅重构 macOS PngCut 的 SwiftUI 视觉、交互呈现和动效；保留所有现有压缩、导入、输出、GIF、队列及错误处理行为。

## 视觉依据

唯一的视觉来源按优先级如下：

1. Figma 设计文件的根画板 `0:1`：<https://www.figma.com/design/TzBxD9oPx2mxNmwzY4BmZe/Untitled?node-id=0-1&m=dev>
2. 用户提供的主界面和设置页截图。
3. `/Users/jinpeng/Downloads/Redesign UI for MacOS App.zip` 中的 `src/App.tsx`，用于尺寸、颜色、状态和动效参数。

ZIP 原型的 720 × 540 是逻辑点尺寸；用户提供的约 1440 × 1080 图像是 Retina 2× 渲染结果，不是另一套大窗口设计。

## 已确认的产品边界

- 保留当前 macOS 应用的文件选择、拖放、目录导入、压缩队列、输出策略、GIF/PNG 序列处理、失败重试、导入决策和打开输出目录行为。
- 只支持并展示 PNG、JPG/JPEG 与 GIF。Figma 原型中的 WEBP 标签必须移除，因为业务层不支持 WebP。
- 默认且最小窗口内容尺寸为 720 × 540 pt。窗口允许继续放大；放大时扩展工作区和列表空间，不拉伸控件、字体或图标。
- 不嵌入 WebView，不复用 React 运行时。ZIP 中的设计和 CSS 动效参数将等价移植为原生 SwiftUI/AppKit 行为。
- Figma 未给出导入后的任务状态。任务列表将作为同一设计语言的必要补充，不引入新业务功能。

## 视觉架构

新增轻量视觉层，数据与业务层保持不变：

- `PngCutVisualTokens`：集中定义 Figma 色板、字体、点尺寸、圆角、描边、阴影、动画曲线和时长。
- `PngCutWindowChrome`：配置 44 pt 浅灰渐变标题区、系统交通灯、居中图标和“图片压缩”标题。
- `PngCutWorkspace`：在空拖放状态与现有任务列表状态之间切换，不重建 `AppModel` 或压缩队列。
- `PngCutDropZone`：实现 520 × 320 pt 虚线拖放区、选择文件按钮和 PNG/JPG/GIF 格式标签。
- `PngCutSettingsSurface`：按 Figma 设置页排版绑定原有输出策略、压缩方式和 GIF 设置。
- `PngCutBottomToolbar`：保留现有无损/平衡模式、打开输出目录与设置动作，应用 Figma 的分段控件和图标状态。
- `PngCutTaskList` 与 `PngCutTaskRow`：复用现有任务模型，呈现等待、处理中、完成、失败与重试。
- `PngCutImportDecisionOverlay`：保留现有决策分支，仅换为这套视觉 token。

预期会改动 `macos/PngCut/App/PngCutApp.swift`、`macos/PngCut/Views/MainWindowView.swift`、`macos/PngCut/Views/SettingsDrawerView.swift` 与 `macos/PngCut/Views/TaskRowView.swift`，并可新增专用视觉组件文件。`AppModel`、域模型、压缩器、文件发现与输出策略不改变业务语义。

## 布局与状态

### 主界面

- 标题区高度 44 pt，浅灰垂直渐变、细分隔线、居中 14 pt 图片图标和 13 pt 半粗标题。
- 内容区使用参考稿的浅灰工作区背景。
- 空状态的拖放区为 520 × 320 pt、18 pt 圆角、1.5 pt 虚线；按钮、提示语和格式标签均按参考稿层级排列。
- 拖入文件时只改变拖放区描边、浅蓝背景和外圈，不改变布局。
- 底栏高度 56 pt，使用参考稿的渐变与顶部分隔线。

### 设置页

- 设置页覆盖内容区，保持标题栏与底栏可见。
- “保存位置”“压缩方式”“GIF 设置”按参考稿的分组、分隔线、单选框、复选框、说明文字和行内控件排版。
- 底栏的压缩模式与设置页的压缩方式绑定同一 `AppSettings.mode`；任一处切换后另一处立刻同步。
- 开启 PNG 序列转 GIF 前，帧率和循环控件可见但降级且不可操作；开启后恢复。自定义帧率的 1–50 校验和错误提示保持现有逻辑。

### 任务列表（补齐状态）

- 任务进入后在同一工作区替换空状态；顶部显示数量和现有“添加文件”动作。
- 每个任务行只显示图标、文件名、必要的大小/进度信息和当前可用动作。
- 处理中显示确定性进度条和百分比；完成显示输出大小与节省比例；失败展示具体失败语义和现有重试动作。
- 列表不自动改变滚动位置，不以颜色作为唯一状态信息。

## 动效规格

默认动效严格移植 ZIP 的 `src/App.tsx` 参数：

| 场景 | 原型参数 | SwiftUI 等价效果 |
|---|---|---|
| 设置页进入/退出 | 240 ms，`cubic-bezier(0.4, 0, 0.2, 1)`，从底部 18 pt | 内容区的 `offset` 与 `opacity` 组合转场 |
| 主界面让位 | 220 ms，`cubic-bezier(0.4, 0, 0.2, 1)`，透明度与 0.97 缩放 | 保持主视图挂载，禁用其命中测试 |
| 无损/平衡滑块 | 220 ms，`cubic-bezier(0.34, 1.56, 0.64, 1)` | 只移动白色选中胶囊，不移动文字或栏位 |
| 分段文字 | 180 ms ease | 颜色和字重过渡 |
| 拖放区、单选、复选、图标 | 150 ms ease | 描边、填充、阴影和按压状态过渡 |
| 主按钮按压 | 100–120 ms | 轻微缩放与渐变亮度，不导致周围布局移动 |

任务列表是原稿没有覆盖的状态：新行与状态文本仅使用上述同一节奏的短淡入。不得添加装饰性循环动画；压缩本身的确定性进度条除外。

所有视觉动画只作用于 `opacity`、`scaleEffect`、`offset`、颜色、描边和阴影，不动画宽高、列表布局或队列状态。系统启用“减少动态效果”时，移除弹性和位移动画，并改为即时或短淡入。

## 流畅度与可用性

- 文件发现和压缩继续在后台运行；主线程只接收合并后的状态和进度更新。
- 连续进度更新不得触发整张任务列表的隐式动画或滚动跳动。
- 打开设置、切换压缩模式、拖入文件的可见反馈目标为 100 ms 内；常规微动效最长 240 ms。
- 不增加网络字体、远程资源、WebView、持续模糊或大面积透明层。
- 所有图标使用现有或新增的矢量资产，保留键盘可达性、可访问标签和可见焦点状态。
- 导入决策显示期间，保持现有禁止新导入的行为，并清晰保留确认和取消路径。

## 验收与测试

1. 在 720 × 540 pt、Retina 2× 条件下，对照主界面和设置页参考截图检查标题栏、拖放区、底栏、间距、色彩、控件状态和 WEBP 缺失。
2. 手工验证 ZIP 动效参数对应的设置页开关、模式滑块、拖放反馈、单选/复选状态与“减少动态效果”降级。
3. 运行现有 `PngCutTests` 和 `PngCutUITests`；更新只依赖布局的 UI 测试断言，保留业务行为覆盖。
4. UI 测试覆盖空状态、任务列表、设置打开/关闭、输出策略、压缩模式、GIF 开关和失败重试的可见性与可点击性。
5. 在真实多文件压缩中通过 Xcode Instruments 的 Core Animation/Time Profiler 检查设置转场、任务滚动和进度更新，不接受明显掉帧、输入冻结或列表跳动。

## 非目标

- 不增加 WebP 支持。
- 不改变 GIF 处理、PNG 序列检测、压缩引擎、输出命名、覆盖策略或导入决策规则。
- 不实现暗色主题；参考稿和现有产品均以浅色外观为基准。
- 不修改 Windows 客户端。
