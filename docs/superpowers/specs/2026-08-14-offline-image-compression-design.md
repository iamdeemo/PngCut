# pngcut 离线 PNG 与 JPEG 压缩设计

## 目标

将 pngcut 从 PNG 专用、部分依赖 Tinify API 的应用，调整为可离线处理 PNG、JPG 与 JPEG 的开源 macOS 应用。PNG 无损使用 oxipng；PNG 平衡使用 pngquant；JPG/JPEG 自动使用 MozJPEG，并在任务列表中标记为“平衡”。

## 授权与发布

应用及其完整对应源码以 GPL v3 发布。发布物保留并列明 oxipng、pngquant、MozJPEG 的版权和许可证文本；DMG、README 与第三方声明说明源码获取方式。移除 Tinify、API Key、Keychain 和网络上传功能。

## 文件发现与任务路由

文件选择和拖入接受 PNG、JPG、JPEG 以及文件夹。其他格式仍被跳过并显示累计数量。

每个任务在入队时记录实际处理引擎和显示档位：

- PNG + 无损：oxipng，显示“无损”。
- PNG + 平衡：pngquant，显示“平衡”。
- JPG/JPEG：MozJPEG，始终显示“平衡”，不依赖当前 PNG 选择。

PNG 的左下角无损/平衡选择仅决定 PNG 任务的默认处理方式；JPG/JPEG 不修改已经排队或已完成的 PNG 任务。

## 压缩行为

pngquant 使用本地可执行文件，默认质量范围 65–80，并启用“不大于原文件”的保护。若达不到最低质量或输出没有更小，任务保留原图并以可理解状态完成，不覆盖原文件。

MozJPEG 通过随应用打包的本地组件重新编码 JPG/JPEG；保留 JPEG 输出扩展名。其是有损模式，因此只归入平衡档，不提供“无损 JPG”误导选项。

现有输出位置策略、临时文件和原子提交机制继续适用，但输出命名改为保留源文件扩展名，不再硬编码 PNG。

## 界面与交互

空状态文案改为“拖入 PNG/JPG 文件或文件夹”。文件选择面板允许 PNG、JPG、JPEG。

任务行展示文件名、大小、进度、节省比例及实际档位。平衡/无损底栏为原生分段式选择：选中滑块横向移动，使用 SwiftUI/macOS 系统默认动画；不使用自定义曲线或渐隐替代滑动。

设置抽屉移除 API 输入、验证按钮和网络提示，只保留输出位置与 PNG 默认压缩方式。平衡模式说明为“本地有损压缩”。

## 错误处理与测试

新增针对 PNG/JPG 发现、引擎路由、输出扩展名、pngquant 质量拒绝和不增大保护的单元测试。对缺少打包二进制、进程失败或无有效输出返回明确失败状态。更新 UI 测试覆盖允许 JPG 的选择提示及分段选择的滑块可访问性。

## 验收标准

1. 无网络、无 API Key 时，PNG 无损/平衡和 JPG/JPEG 平衡均可入队处理。
2. 导入 JPG/JPEG 任务行显示“平衡”和 MozJPEG 处理结果。
3. PNG 平衡不再访问 Tinify。
4. 重新打开应用后 PNG 默认档位与输出位置保持不变。
5. 底栏档位切换时选中滑块以 macOS 默认横向动画移动。
6. Release 构建、单元/UI 测试和最终 DMG 验证通过；DMG 明确为未公证的直接下载应用。
